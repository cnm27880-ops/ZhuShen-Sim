# 給哈基米的指令：修改詞條庫文字（`src/data/codexTags.js`）

> 這份文件是給哈基米（Gemini）看的。露葵會把 `codexTags.js` 的內容（或其中一段）貼給你，你照下面規則改文字，再把改好的內容完整貼回去。

## 你在改什麼

遊戲裡有一個「詞條庫」懸浮球，玩家點開可以查所有詞條。詞條庫的內容全部放在 `src/data/codexTags.js` 這一個檔案：

- **人物詞條**：171 個（`export const CODEX_PEOPLE`），原稿編號 `no` 從 1 到 171。
- **關卡詞條**：22 個（`export const CODEX_ENVS`），原稿編號 `no` 從 1 到 22。

這些內容原本就是你寫的標籤庫。現在露葵想請你潤飾、改寫其中的文字。

## 檔案長什麼樣子

每個詞條佔**一行**，是一個 JSON 物件，例如：

```js
{"no":112,"id":"born_strong","gameId":"born_strong","name":"天生神力","rarity":"N","kind":"stat","tone":"good","section":"身體與戰鬥天賦","desc":"從小力氣就比別人搬磚塊多一倍，一拳能打死一頭牛。","effect":"物理攻擊力 +15%，負重上限 +2。","summary":"物攻 +15%，負重 +2","event":"遇到被巨石堵住的寶箱房時，可不消耗體力直接一拳打碎巨石。"},
```

## 人物詞條：哪些欄位可以改

| 欄位 | 意思 | 可以改嗎 |
|---|---|---|
| `desc` | 標籤描述（玩家看到的簡短介紹） | 可以，這是主要要潤飾的 |
| `effect` | 效果說明（畫面上只顯示這一行「效果」） | 可以改措辭；**數字與機制不要動**（見下方「數字規則」） |
| `event` | 觸發事件舉例 | 可以，可以改寫得更好笑、更有畫面 |
| `name` | 顯示名稱 | 可以，但改名要先問露葵（`gameId` 不是空的詞條，名稱以遊戲內標籤為準） |
| `fullName` | 原稿的完整名稱（括號註解） | 可以 |

## 人物詞條：這些欄位絕對不要改

`no`、`id`、`gameId`、`rarity`（稀有度）、`kind`、`tone`（好壞顏色：good 好／bad 壞／mixed 中性）、`section`、`weight`。

這些會影響篩選、好壞顏色，以及「開著小人檔案時他的詞條自動置頂」；改了會弄壞遊戲。想調整稀有度或好壞顏色，請**列出來問露葵**，不要自己改。

## 關卡詞條：哪些欄位可以改

| 欄位 | 意思 | 可以改嗎 |
|---|---|---|
| `desc` | 環境描述 | 可以 |
| `effect` | 效果說明 | 可以改措辭；數字與機制不要動 |
| `countered` | 它克誰（極度克制的人物詞條與對象） | 可以改措辭；**【】裡的詞條名稱必須是人物詞條裡真的存在的名稱** |
| `favored` | 誰佔優勢（極大優勢的人物詞條與對象） | 同上 |
| `event` | 觸發事件舉例 | 可以 |
| `name`、`sub` | 名稱、名稱旁的小字（例如「資本主義法則」） | 可以，改名要先問露葵 |

不要改：`no`、`id`、`gameId`。

## 數字規則

- 每個詞條的數字（例如 +15%、機率 40%、-20% 壓力）是之後實裝進遊戲的規格，**除非露葵明確要求，不要改數字、不要加減效果、不要改機制**。
- 只改文字表達：讓描述更好笑、更像「主神空間打工日記」的黑色幽默，讓效果文字更清楚好懂。
- 稀有度的數值強度要符合你自己寫的「第五部分：標籤分級與數值平衡框架」；如果你覺得某個數字不合理，**另外列一份清單給露葵**，不要直接改。

## 文字風格

- 繁體中文。
- 一個詞條的 `desc` 建議 1～2 句話，不要超過 80 字。
- 玩家會在手機上看，句子要短。
- 不要用 emoji；不要用 Markdown 符號（`**`、`#` 這些）。
- 可以使用「」、【】、（）、——。
- 不要出現真實人物或真實品牌。

## 一定要遵守的格式規則（寫錯整個遊戲會壞）

1. **每個詞條仍然只佔一行**，不要換行、不要把一個詞條拆成多行。
2. 所有字串用**半形雙引號** `"`。文字裡面如果要用引號，請用「」，不要用半形 `"`。
3. 物件欄位之間用半形逗號 `,`，每一行結尾都要有逗號 `,`。
4. **不要新增、刪除、重新排列詞條**，數量要維持：人物 171 個、關卡 22 個。
5. 不要改檔案最上面的 `//` 註解，也不要改 `export const` 那幾行。
6. 沒有要改的詞條，原樣保留。
7. 每個詞條的 `desc`、`effect` 都**不可以變成空字串**（遊戲會檢查）。

## 怎麼交稿

1. 露葵一次可能只貼一部分（例如編號 1～30），你只回覆那一部分。
2. **回覆整段完整內容**（含沒改的行），不要只回覆有改的行，也不要用「其他不變」這種省略。
3. 用一個程式碼區塊（```js）包起來。
4. 程式碼區塊後面，另外列出：
   - 你**改了哪些編號**；
   - 你覺得**需要露葵決定**的事（例如稀有度、好壞顏色、數字、改名建議）。

## 這份檔案之外，哈基米不用管的東西

- 詞條庫畫面上的固定字樣，例如「它克誰（極度克制）」「誰佔優勢（極大優勢）」，不在這個檔案裡，在 `src/ui/codex.js`。想改措辭請**告訴露葵**，由小克改。
- **已經做進遊戲引擎的詞條**（`gameId` 不是 `null`，目前人物 32 個、關卡 5 個）：畫面上的「效果」顯示的是引擎真正在算的數值，由程式自動產生，**改這個檔案的 `effect` 不會顯示**；其餘詞條才顯示你寫的 `effect`。
- 關卡詞條 13～22 還沒有潤飾過（上次交稿在第 13 個被截斷），歡迎補完。
- 遊戲事件文本（關係事件、日誌）是另一份工作，不在這個檔案裡。
